# ГБУК-ПРАКТИКА — описание для проверки

Рабочее веб-приложение для ГБУК г. Москвы «Театр «Практика»: календарь сроков и обязательств, налоговый календарь, реестр договоров, архив документов, проекты документов и счетов, помощница «Глафира» (подсказки по работе приложения).

- Сайт: https://malamut2022.github.io/GBUK-PRAKTIKA/
- Текущая версия указана в шапке сайта, в значке в левом нижнем углу и в разделе «Помощь → Журнал обновлений».

## Состав репозитория

| Файл | Назначение |
|---|---|
| `index.html` | Всё приложение: разметка, стили и JavaScript в одном файле, без сборки |
| `glafira-demo.html` | Старая демонстрационная страница помощницы Глафиры |
| `.github/workflows/pages.yml` | Публикация на GitHub Pages при изменении ветки `main` (без сборки и сторонних зависимостей) |

## Архитектура и данные

- **Сервера нет.** Это статический сайт: браузер загружает `index.html`, вся логика выполняется на компьютере пользователя.
- **Данные никуда не отправляются.** В коде нет `fetch`, `XMLHttpRequest`, `WebSocket` и `sendBeacon`, нет аналитики и счётчиков, cookies не используются.
- **Где хранятся данные:** только в браузере пользователя на этом компьютере.
  - `localStorage`: `gbuk_praktika_v9_events` (дела и сроки), `gbuk_praktika_contract_registry_v1` (реестр договоров), `gbuk_praktika_tax_settings_v1` (настройки налогового календаря), `gbuk_glafira_dialogue_v1` (история вопросов Глафире), а также служебные отметки о резервных копиях и положении окна Глафиры.
  - `IndexedDB`: `gbuk_documents_v1` (архив документов, файлы), `gbuk_contract_archive_v1` (текст и файлы договоров).
  - Приложение запрашивает у браузера постоянное хранилище (`navigator.storage.persist`), чтобы данные не удалялись автоматически при нехватке места.
- **Резервные копии** пользователь скачивает вручную: JSON (дела и реестр) и ZIP (все документы, разложенные по папкам типов, с файлом `manifest.json`).
- **Другие пользователи и устройства** этих данных не видят: общего хранилища пока нет.

## Внешние ресурсы

Скрипты загружаются только тогда, когда пользователь открывает файл, из которого нужно извлечь текст. Файлы при этом не передаются: обработка идёт в браузере.

| Библиотека | Версия | Откуда | Когда |
|---|---|---|---|
| pdf.js (Mozilla) | 3.11.174 | cdnjs.cloudflare.com | чтение текста из PDF |
| mammoth | 1.9.0 | cdn.jsdelivr.net | чтение текста из DOCX |
| tesseract.js | 5.1.1 | cdn.jsdelivr.net | распознавание сканов (OCR); дополнительно скачивает ядро распознавания с cdn.jsdelivr.net и языковые данные rus/eng с tessdata.projectnaptha.com |

**Голосовой ввод Глафиры** (кнопка 🎤) использует встроенное распознавание речи браузера. В Google Chrome звук обрабатывают серверы Google. Функция включается только нажатием на кнопку микрофона. Озвучивание ответов работает локально.

Остальные адреса в коде (nalog.gov.ru, pravo.gov.ru, sfr.gov.ru, онлайнинспекция.рф, сайт театра) — это обычные ссылки, по которым пользователь переходит сам.

## Как проверить

1. Откройте сайт, затем DevTools → Network. При обычной работе (календарь, налоги, архив, Глафира) сетевых запросов к сторонним серверам нет. Обращения к CDN появляются только при открытии PDF, DOCX или скана в разделе «Договоры».
2. DevTools → Application → Local Storage / IndexedDB покажут все сохранённые данные. Других мест хранения нет.
3. Поиск по `index.html`: `fetch(`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, `document.cookie` не встречаются.

## Известные ограничения

- Нет входа по паролю и разграничения прав: доступ к данным есть у любого, кто сидит за этим компьютером в этом браузере.
- Нет антивирусной проверки загружаемых файлов. Приложение проверяет только расширение, размер (архив — до 50 МБ, договоры — до 20 МБ) и сигнатуру файла договора. Файлы не исполняются, а только хранятся и открываются средствами браузера.
- Скрипты с CDN подключаются без SRI, на странице нет Content-Security-Policy. Если нужно, библиотеки можно разместить вместе с приложением на сервере театра, добавить CSP и полностью отказаться от внешних ресурсов (OCR тогда тоже будет работать локально).
- Данные хранятся на одном устройстве. Для общей работы нужен сервер или сетевая папка (см. ниже).

## Размещение на ресурсах театра (обсуждается)

Требуется до 20 ГБ под документы. Возможны два варианта:

1. **Сетевая папка** (SMB, подключается в Finder). Приложение сохраняет документы прямо в неё через File System Access API. Работает в Chrome и Edge, в Safari не работает. Права доступа задаются правами на папку.
2. **Сервер** (Linux/Windows или виртуальная машина), где запускается приложение. Данные общие для всех пользователей, вход по паролю, резервное копирование средствами сервера. Нужны: HTTPS-адрес во внутренней сети, место под файлы и база данных (SQLite или PostgreSQL).
