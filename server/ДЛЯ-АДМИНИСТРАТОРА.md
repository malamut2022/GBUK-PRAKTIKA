# ГБУК-ПРАКТИКА: пояснительная записка для ИТ-администратора

**Что нужно:** разместить внутреннее рабочее приложение бухгалтерии театра «Практика» на сервере театра.
**Кто работает:** Серж, Людмила, Екатерина, а позже, возможно, бухгалтер.
**Ответственный со стороны пользователей:** Серж.
**Версия приложения:** 14.0.

## 1. Что это за приложение

Приложение помогает бухгалтерии: календарь сроков и обязательств, налоговый календарь, реестр договоров, архив документов (сканы, PDF, Word, Excel), проекты договоров и счетов, подсказки «Глафиры».

Сейчас демоверсия без входа работает на GitHub Pages: каждый пользователь хранит данные в своём браузере. Серверная версия добавляет:

- **личный вход** по логину и паролю для каждого сотрудника;
- **общие данные**: все видят одни и те же дела, реестр и документы;
- **хранение документов на сервере** в пределах выделенного места (по умолчанию 10 ГБ);
- **журнал входов и действий**.

## 2. Требования к серверу

| Что | Требование |
|---|---|
| ОС | Linux (рекомендуется), Windows Server или macOS |
| Программы | Node.js 18 или новее (подойдёт LTS 20 или 22). **Больше ничего: ни `npm install`, ни базы данных, ни сторонних пакетов** |
| Ресурсы | 1 ядро, 512 МБ памяти |
| Диск | 10 ГБ под документы и около 1 ГБ запаса под служебные файлы и ежедневные копии |
| Сеть | доступ сотрудников к серверу по HTTPS из сети театра (или через VPN) |
| Интернет с сервера | не нужен |
| Интернет у пользователей | нужен только для чтения текста из PDF, DOCX и сканов: браузер загружает библиотеки с cdnjs.cloudflare.com, cdn.jsdelivr.net и tessdata.projectnaptha.com. Без доступа к ним работает всё остальное |

## 3. Из чего состоит

| Файл | Назначение |
|---|---|
| `server/server.js` | весь сервер (~560 строк, только встроенные модули Node.js) |
| `server/public/gbuk-server.js` | подключение страницы к серверу: синхронизация данных, имя пользователя в шапке, раздел «Доступы» (~180 строк) |
| `index.html` | само приложение (тот же файл, что и в демоверсии) |
| `server/data/` | данные; создаётся при первом запуске, путь можно изменить переменной `DATA_DIR` |

Код открыт для проверки: https://github.com/malamut2022/GBUK-PRAKTIKA

## 4. Установка (Linux, пример)

```bash
# 1. Пользователь и папка
sudo useradd --system --home /opt/gbuk --shell /usr/sbin/nologin gbuk
sudo git clone https://github.com/malamut2022/GBUK-PRAKTIKA.git /opt/gbuk/app
sudo mkdir -p /srv/gbuk-data && sudo chown -R gbuk:gbuk /opt/gbuk /srv/gbuk-data && sudo chmod 700 /srv/gbuk-data

# 2. Первичная настройка: создаются пользователи и выводятся временные пароли
sudo -u gbuk DATA_DIR=/srv/gbuk-data node /opt/gbuk/app/server/server.js init
```

Команда `init` выведет таблицу с логинами `serzh`, `lyudmila`, `ekaterina` и временными паролями. **Передайте каждому только его пароль, лично.** При первом входе приложение потребует сменить временный пароль на свой.

Сервис systemd, файл `/etc/systemd/system/gbuk.service`:

```ini
[Unit]
Description=GBUK-PRAKTIKA
After=network.target

[Service]
User=gbuk
WorkingDirectory=/opt/gbuk/app
Environment=DATA_DIR=/srv/gbuk-data
Environment=PORT=8080
Environment=HOST=127.0.0.1
Environment=TRUST_PROXY=1
Environment=QUOTA_GB=10
ExecStart=/usr/bin/node server/server.js start
Restart=on-failure
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/srv/gbuk-data
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now gbuk
```

HTTPS через nginx (сертификат театра или внутреннего центра сертификации):

```nginx
server {
    listen 443 ssl;
    server_name gbuk.praktika.local;          # адрес во внутренней сети
    ssl_certificate     /etc/ssl/gbuk.crt;
    ssl_certificate_key /etc/ssl/gbuk.key;
    client_max_body_size 60m;                 # документы до 50 МБ
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

Если nginx нет, сервер сам принимает HTTPS: задайте `TLS_CERT`, `TLS_KEY` и `HOST=0.0.0.0`, переменную `TRUST_PROXY` не задавайте.

На **Windows** порядок тот же: установить Node.js, выполнить `init`, а запуск оформить службой (например, через NSSM) командой `node server\server.js start` с теми же переменными окружения.

## 5. Настройки (переменные окружения)

| Переменная | По умолчанию | Значение |
|---|---|---|
| `DATA_DIR` | `server/data` | папка с данными |
| `PORT` / `HOST` | `8080` / `0.0.0.0` | адрес и порт |
| `QUOTA_GB` | `10` | сколько места можно занять документами |
| `MAX_FILE_MB` | `50` | максимальный размер одного файла |
| `TLS_CERT`, `TLS_KEY` | — | сертификат и ключ, если сервер сам принимает HTTPS |
| `TRUST_PROXY` | выключено | `1`, если сервер стоит за nginx: тогда учитываются `X-Forwarded-For` и `X-Forwarded-Proto` |
| `SESSION_IDLE_HOURS` | `12` | выход после бездействия |
| `SESSION_MAX_DAYS` | `7` | максимальная длительность сессии |
| `BACKUPS_KEEP` | `30` | сколько дней хранить ежедневные копии служебных данных |
| `CSP` | включено | `off` отключает заголовок Content-Security-Policy (только для диагностики) |

## 6. Пользователи и права

| Роль | Кто | Что может |
|---|---|---|
| Владелец | Серж | работать со всеми данными; в разделе «Доступы» **создавать, блокировать и удалять доступы только с ролью «Бухгалтер»**, сбрасывать им пароль, смотреть журнал входов и действий |
| Сотрудник | Людмила, Екатерина | работать со всеми данными |
| Бухгалтер | создаёт Серж | работать со всеми данными |

Изменить роль, создать другого владельца или сотрудника через интерфейс нельзя: это проверяет сервер, а не только кнопки на странице. Если сотрудник забыл пароль или владелец потерял доступ, администратор выполняет:

```bash
sudo -u gbuk DATA_DIR=/srv/gbuk-data node /opt/gbuk/app/server/server.js reset-password lyudmila
sudo -u gbuk DATA_DIR=/srv/gbuk-data node /opt/gbuk/app/server/server.js list-users
```

## 7. Безопасность

- **Пароли** хранятся только как хеш scrypt с солью (N=16384), сравнение с постоянным временем. Требования: не короче 10 символов, буквы и цифры, без логина внутри. Временный пароль нужно сменить при первом входе.
- **Подбор паролей:** после 5 неверных попыток логин блокируется на 15 минут, после 30 попыток с одного IP блокируется весь IP. Текст ошибки не подсказывает, существует ли логин.
- **Сессии:** случайный токен (256 бит), на сервере хранится только его SHA-256. Cookie `HttpOnly; SameSite=Strict` (+ `Secure` при HTTPS). Выход после 12 часов бездействия. При смене пароля и блокировке остальные сессии пользователя закрываются.
- **Подделка запросов (CSRF):** `SameSite=Strict`, обязательный заголовок `X-GBUK` и проверка `Origin` для всех изменяющих запросов.
- **Заголовки:** Content-Security-Policy (скрипты только со страницы приложения, с сервера и трёх указанных CDN; `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, HSTS при HTTPS.
- **Документы:** хранятся под случайными именами, имя файла от пользователя в путях не используется, поэтому выйти за пределы папки нельзя. Загруженные HTML и текст отдаются с `Content-Security-Policy: sandbox`, то есть скрипты из них не выполняются. Скачивание идёт как `attachment`. Действуют лимиты на размер файла и общий объём.
- **Наружу ничего не отправляется:** сервер не обращается в интернет, в приложении нет аналитики и счётчиков.
- **Голосовой ввод Глафиры** (кнопка 🎤) в Google Chrome передаёт звук на распознавание в Google. Функция включается только вручную. При необходимости её можно запретить политикой браузера или попросить нас отключить.
- **Права на файлы данных:** `600`, на папку — `700`.

**Чего нет и что рекомендуем:**
- нет двухфакторного входа: публикуйте сервер только во внутренней сети или через VPN;
- нет встроенного антивируса: включите проверку папки `DATA_DIR/docs/files` антивирусом сервера;
- нет SRI для библиотек с CDN: по запросу разместим их на самом сервере.

## 8. Где лежат данные и резервное копирование

```
DATA_DIR/
  users.json          пользователи (хеши паролей)
  sessions.json       активные сессии (хеши токенов)
  state.json          общие данные: дела, реестр договоров, настройки
  docs/meta.json      описания документов
  docs/files/         сами файлы документов
  audit.log           журнал входов и действий (JSON по строке)
  backups/ГГГГ-ММ-ДД/ ежедневные копии users.json, state.json, docs/meta.json (хранятся 30 дней)
```

Сервер сам каждый день копирует служебные файлы, а удалённые пользователями документы окончательно стирает из корзины через 30 дней. **Файлы документов сервер не дублирует**, поэтому **резервное копирование всей папки `DATA_DIR` средствами театра обязательно** (снимки, rsync, бэкап-система). Чтобы восстановить данные, остановите сервис, верните папку и запустите сервис снова.

Дополнительно пользователи сами могут скачать все документы одним ZIP-архивом прямо из приложения.

## 9. Обновление

```bash
cd /opt/gbuk/app && sudo -u gbuk git pull && sudo systemctl restart gbuk
```

Данные лежат отдельно в `DATA_DIR` и при обновлении не затрагиваются. Номер версии виден в приложении в левом нижнем углу.

## 10. Проверка после установки

1. Откройте адрес сервера: должна появиться страница «Вход». Без входа приложение и API недоступны (код 401).
2. Войдите под `serzh` по временному паролю: приложение попросит сменить пароль, затем откроется. В шапке написано «Серж · Владелец», в меню «Управление» есть пункт «Доступы».
3. Войдите под `lyudmila` в другом браузере: дело, добавленное Сержем, появится у неё в течение 15 секунд.
4. Загрузите документ в «Документы → Архив документов»: файл появится в `DATA_DIR/docs/files`.
5. В «Доступах» создайте тестового бухгалтера, войдите под ним, затем заблокируйте и удалите его.
6. Пять раз введите неверный пароль: вход заблокируется на 15 минут.
7. Откройте PDF и скан в разделе «Договоры» и проверьте, что текст распознаётся. Для этого у пользователей нужен доступ к CDN из раздела 2.

Перед передачей сервера в работу эти проверки прошли автоматически (62 теста: вход, роли, совместная работа, документы, лимит места, защита от CSRF и выхода за пределы папки).
